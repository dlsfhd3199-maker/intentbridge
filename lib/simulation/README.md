# Performance Lab · Rule-based Simulation

`../simulation.ts`는 순수 계산 서비스, `baseline.ts`는 기존 Mock Connector 기반 Baseline 조합,
`store.ts`는 광고주·기간·채널 조합별 Mock 설정 저장입니다. 운영 추천은 `../recommendations.ts`입니다.
실제 API, 광고 계정, AI 모델은 호출하지 않습니다.

## 기준 데이터

기존 JSON 및 Funnel 집계를 그대로 사용합니다. 브랜드 A 30일은 유입 1,284명,
직접 구매 41건, 회수 구매 53건, 총 94건, 매출 13,690,000원, 광고비 3,200,000원입니다.
요청에 적힌 예시 수치로 기존 데이터를 덮어쓰지 않습니다.
7일·14일은 기존 24%·49% 예시 스냅샷이며 실제 일자별 측정이 아닙니다.

재공략 풀은 **현재 미구매 Audience + 기간 내 회수 구매**라는 합성 코호트입니다.
브랜드 A는 742 + 53 = 795명이며 기준 회수율은 53/795입니다.
현재 Audience 742명으로 과거 회수율을 계산하지 않습니다. 이 풀 재구성도 Mock 가정입니다.

## 공식

`V, W, C, H, D, R`은 기존 유입/조회/장바구니/결제진입/직접구매/회수구매,
`P`는 위 합성 재공략 풀입니다. `l, c, h, e, a, m`은 각각 6개 레버의 % 값을 100으로 나눈 값입니다.
`r(x,y)`는 분모가 0이면 0, 아니면 `min(1,x/y)`입니다.

1. 예상 유입 `V' = round(Organic + Paid × (1+a))`. 유입 예산은 Organic에 영향을 주지 않습니다.
2. 예상 조회 `W' = round(V' × min(1, r(W,V) × (1+l)))`.
3. 예상 장바구니 `C' = round(W' × min(1, r(C,W) × (1+c)))`.
4. 예상 결제진입 `H' = round(C' × r(H,C))`. 이 단계의 전환율은 고정합니다.
5. 예상 직접구매 `D' = round(H' × min(1, r(D,H) × (1+h)))`.
6. 예상 재공략 풀 `P' = round((V'-D') × r(P,V-D))`.
7. 예상 회수구매 `R' = round(P' × min(1, r(R,P) × (1+e) × (1+m)))`.
8. 예상 총구매 `D'+R'`. 각 단계 인원은 상위 단계, 회수 구매는 재공략 풀 이하로 제한합니다.
9. 예상 매출 `round(D' × 직접 평균 주문액 + R' × 회수 평균 주문액)`. 평균 주문액은 경로별 기존 매출/구매로 고정합니다. 기준 구매 0건이면 해당 평균액은 0입니다.
10. 예상 광고비 `round(유입 광고비 × (1+a) + 재공략 광고비 × (1+m))`.
11. CPA = 광고비/총구매, ROAS = 매출/광고비×100. 분모가 0이면 `null`이며 UI에 산출 불가를 표시합니다.

전환율 개선은 **상대 배수**입니다. 기존 30%에서 +10%이면 33%이며, 40%가 아닙니다.
단계별 반올림을 적용하고 모든 레버는 범위를 제한합니다. 비정상 값은 0%로 정규화합니다.
유입·예산 간 선형 관계, 고정 주문액과 재공략 자격 비중, 회수 효율·예산의 곱은 설명 가능한 단순 가정입니다.
실제 시장 반응, 증분 기여, 광고 빈도·포화, 통계적 불확실성은 모델링하지 않습니다.

## 진단·추천·비교

- Mock 목표: 조회 85%, 장바구니 45%, 결제진입 60%, 결제완료 40%, 회수 10%. 업계 벤치마크가 아닙니다.
- 목표 달성 비율 100% 이상 Healthy, 85% 이상 Watch, 60% 이상 Opportunity, 그 미만 Critical. 모수가 없으면 UI에 데이터 없음.
- 개선 여지 = `max(0, round(단계 모수 × 목표율) - 현재 단계 인원)`. 이를 구매 증가로 해석하거나 단계끼리 합산하지 않습니다.
- 추천 우선순위: CPA/ROAS 3% 이상 악화 시 예산 변화 초기화 → 목표 대비 낮은 단계의 개선 가정 → 회수 CPA가 더 낮으면 일부 예산 이동. 최대 3개만 표시합니다.
- 결제진입 단계 자체의 개선 레버는 없으므로 관련 추천은 결제완료 개선의 대안 가정임을 명시합니다.
- 예산 이동은 재공략 기준 광고비의 15%를 유입 쪽에서 감액하는 예시이며 정수 % 반올림/레버 하한 때문에 정확한 동일 총예산은 보장하지 않습니다. 변경 광고비를 함께 표시합니다.
- 구매·매출·ROAS 증가와 CPA 감소를 개선, 반대를 악화로 표시합니다. 광고비 변화는 중립입니다. ROAS 차이는 %p입니다.
- 차트 2개: 공통 유입 척도의 퍼널, 단위별 독립 척도의 매출/CPA/ROAS 비교. Forecast는 항상 Violet 및 DEMO FORECAST로 구분합니다.

## Preset·Confidence·Breakdown

Preset 및 What-if 값은 `data/mock/simulation-config.ts`에 있습니다. What-if는 선택한 레버만 해당 값으로 설정합니다.
Total Budget +20%는 유입/재공략 예산 레버를 둘 다 +20%로 설정합니다. 다른 전환율 레버는 유지합니다.
Reset은 모든 레버를 0%로 되돌려 Baseline과 동일한 값을 만듭니다.

Confidence는 레버 절댓값의 최댓값이 5% 이하 HIGH, 20% 이하 MEDIUM, 그 이상 LOW입니다.
통계적 신뢰도나 성공 확률이 아닙니다. 보수적 HIGH / 추천 MEDIUM / 공격적 LOW입니다.

Breakdown은 Landing → Cart → Checkout → Retargeting Efficiency → 두 Budget 순서로 적용하며
각 단계 전체 시뮬레이션 구매 수에서 직전 값을 뺍니다. 음수 변화도 표시합니다.
상호작용 및 반올림이 한 번만 포함되어 `Baseline + 모든 delta = Projected`를 만족합니다.
순서에 의존하는 계산 설명이며 인과적 기여도 추정은 아닙니다.

## 저장

`intentbridge:simulation:v1:<advertiser>:<period>:<source>:<retarget>` 키로 Scenario, Lever, Forecast만 저장합니다.
계정·토큰·개인 데이터는 저장하지 않습니다. 광고주/기간/채널별 분리, 손상 JSON 방어,
저장소 거부 시 메모리 대체를 지원합니다. 저장된 Forecast는 신뢰하지 않고 현재 Baseline으로 재계산합니다.
앱 공통 광고주/기간 선택 자체는 기존처럼 새로고침 시 A/30일로 초기화되지만 각 설정은 보존됩니다.
